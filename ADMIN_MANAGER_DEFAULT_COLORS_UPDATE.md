# Обновление дефолтных цветов администратора и менеджера

## Изменение

Администратор и менеджер теперь используют фиксированные дефолтные цвета, которые не зависят от динамических цветов стадий.

## Реализация

### 1. Добавлены константы дефолтных цветов

```typescript
// Дефолтные цвета для администратора и менеджера
const DEFAULT_ADMIN_COLORS = {
  admin: '#ef4444', // red-500 - красный
  manager: '#3b82f6', // blue-500 - синий
}
```

### 2. Обновлена логика приоритетов

**Новый порядок приоритетов:**
1. **Дефолтные цвета администратора и менеджера** (высший приоритет)
2. Кастомный цвет роли
3. Цвет связанной стадии
4. Цвет стадии по имени
5. Дефолтный серый цвет

### 3. Изменения в функциях

#### getRoleColor()
```typescript
export function getRoleColor(roleName: string, roleData?: any, stagesData?: any[]): string {
  // Администратор и менеджер всегда используют дефолтные цвета
  if (DEFAULT_ADMIN_COLORS[roleName]) {
    return DEFAULT_ADMIN_COLORS[roleName]
  }
  
  // ... остальная логика
}
```


## Результат

### Цвета ролей:
- **Администратор** → всегда красный (`#ef4444`)
- **Менеджер** → всегда синий (`#3b82f6`)
- **Дизайнер** → цвет стадии "Дизайн" (динамический)
- **Печатник** → цвет стадии "Печать" (динамический)
- **Работник цеха** → цвет стадии "Цех" (динамический)

### Преимущества:
- ✅ Администратор и менеджер имеют стабильные, узнаваемые цвета
- ✅ Остальные роли остаются динамическими
- ✅ Система остается гибкой для новых ролей
- ✅ Сохранена обратная совместимость

## Тестирование

1. **Проверка дефолтных цветов:**
   - Администратор всегда красный
   - Менеджер всегда синий
   - Цвета не меняются при изменении стадий

2. **Проверка динамических цветов:**
   - Дизайнер, печатник, работник цеха используют цвета стадий
   - Изменение цвета стадии обновляет цвета ролей

3. **Проверка кастомных цветов:**
   - Роли с кастомными цветами отображаются корректно
   - Кастомные цвета имеют приоритет над стадиями (кроме админа и менеджера)
