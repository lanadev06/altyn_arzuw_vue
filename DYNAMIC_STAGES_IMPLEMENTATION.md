## Ключевые особенности новой системы

### 🔄 Динамические стадии
- Стадии создаются и управляются через админку
- Каждая стадия может иметь свои роли
- Стадии имеют цвета для визуального отличия

### 👥 Назначения по стадиям
- Сотрудники назначаются на конкретные стадии
- Каждая стадия может иметь несколько ролей
- Назначения сохраняются с привязкой к стадии

### 🎯 Гибкость выбора
- Для товаров: выбираются стадии из всех доступных
- Для заказов: выбираются стадии из доступных стадий продукта
- Можно исключать ненужные стадии для конкретных заказов

### 🔧 Обратная совместимость
- Старая система с чекбоксами продолжает работать
- Существующие товары и заказы не пострадают
- Постепенная миграция на новую систему

## Структура данных

### Стадии (stages)
```sql
- id: number
- name: string (например: "design", "print")
- display_name: string (например: "Дизайн", "Печать")
- color: string (hex цвет)
- order: number (порядок)
- is_active: boolean
- is_initial: boolean
- is_final: boolean
```

### Роли стадий (stage_role)
```sql
- stage_id: number
- role_id: number
- is_required: boolean
- auto_assign: boolean
```

### Назначения товаров (product_assignments)
```sql
- product_id: number
- user_id: number
- role_type: string
- stage_id: number (НОВОЕ ПОЛЕ)
- is_active: boolean
```

### Назначения заказов (order_assignments)
```sql
- order_id: number
- user_id: number
- role_type: string
- stage_id: number (НОВОЕ ПОЛЕ)
- status: string
```

## API изменения

### Новые endpoints
- `GET /api/stages` - получить все стадии
- `GET /api/stages/{id}/roles` - получить роли стадии
- `POST /api/stages/{id}/roles` - добавить роль к стадии
- `DELETE /api/stages/{id}/roles/{role_id}` - удалить роль со стадии

### Обновленные endpoints
- `POST /api/products/{id}/assignments` - теперь поддерживает `stage_id`
- `POST /api/orders/{id}/assignments` - теперь поддерживает `stage_id`
